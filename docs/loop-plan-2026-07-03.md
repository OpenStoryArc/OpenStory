**Two research findings drive the next work:**
1. **Data load is the real NFR problem.** On a 15k-event session, unpaginated `/records` = **91 MB / 1.3 s**,
   fetched **2–4×** because loaders don't share a cache. The RxJS store already caches (`streams/sessions.ts`,
   `loadedSessions`) but only the Live tab uses it. A cache = a Read Model = a green sticky on the Storm board.
2. **The UI's navigation graph ≠ the data's graph yet.** 7 dead-ends where the data connects but no control verb
   walks it. Each is a `navigateToEntity` to grow; closing one bumps ActionGraph coverage and gets a live
   `nav_survey` landing test for free.

## The prioritized queue (what the loop works through, in order)

**P1 — SNAPPY (shared read-model cache; the biggest win Max keeps asking for).**
- Build a shared `useSessionRecords(sessionId)` hook — a keyed promise cache (`Map<id, Promise<records>>`) or the
  existing RxJS store — so the whole-session records fetch happens **once**. Route Story's `SessionSummaryLoader`,
  Explore's `SessionVizLoader` + `SessionTimeline` + `conversation/ConversationView` through it. TDD the pure cache.
- **P0 quick win:** point `SessionSummaryLoader` at `/api/sessions/{id}/summary` (502 B) not `/records` (91 MB).
- Paginate the whole-session loaders like Live's `streamSessionRecords` (`lib/session-records.ts`); add
  `limit`/`before_seq` to `/conversation` server-side (`api.rs`).
- Make `/summary` cheap server-side — serve token/count aggregates from projections, not a 15k-event rescan.
- Shaped skeletons on the two conversation views (currently bare "Loading…").
- Add the record cache to the Storm board as a green **read-model** sticky (keep the architecture honest).

**P2 — GROW THE CANOPY (close the navigation dead-ends; each: add `via` in action-graph.ts + wire the affordance
+ add to `nav_survey` drivable set + re-run the survey so coverage ticks 53% → up).**
- `carry-session-across-tabs`: `App.handleSwitchTab` preserves `sessionId` (Live→Story keeps the session).
- `event→turn`: from an event, climb to its turn in Story.
- `file→session`: click a file → its impact across sessions (the `file_impact` endpoint already exists).
- `subagent→parent`: from a spawned agent, climb to its spawner.
- `toolcall↔result`: jump between a call and its result.
- `error→event`: from an error, land on the exact event, everywhere.
- `plan→turn`: from a plan, open the turn that authored it.

**P3 — LOCK IN THE JOURNEYS (E2E arising from the domain).** Turn the Storm board's `JOURNEYS` into real
Playwright specs in `e2e/tests/`: "read a session's story" (Live→session→Story→turn→source), "agent drives the
mirror", "follow the user & act in rests". Each journey = one E2E requirement. Reuse the seed-data harness.

**P4 — POLISH / FOLLOW-UPS.** `fullTimestamp` on event rows / `SessionSummaryHeader` / `PresentBanner`;
`useResizablePanel` grip on Story + Live sidebars; Storm board polish (hover tooltips, deep-link a sticky, more
journeys); optional interaction-writer async fix (documented in perf-metronome.md, YAGNI unless load grows);
a real-browser (slower-drain) broadcast-drop test.
