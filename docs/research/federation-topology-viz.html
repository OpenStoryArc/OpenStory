Federation topology + test plan

Companion to docs/research/jetstream-sources-federation.md. The research doc is the spec; this page is the picture.

Phase 1 subject scheme (already in master): 

events.{host}.{project}.{session}.main
events.{host}.{project}.{session}.agent.{agent_id}

Each leaf binds only its own namespace events.{host}.> — that's what makes federation safe (no cross-pollination, no double-counting).

1 · The three planned topologies

Each shape flips the topology while holding the invariant constant: fully_mirrored cold, with catch-up OFF. Pure transport convergence.

2 · Per-node stream architecture

Two streams per node — the key Idea A mechanic. The local events stream is publish-only and bound to just this host's namespace; the events-mirror stream is source-only (no subjects → no publishers → structurally cannot loop).

  • Self-origin exclusion. A leaf's mirror excludes events that originated on that leaf — so local events ∪ events-mirror is exactly the fleet view, no duplication.
  • One consumer-side change. The OpenStory consumer must read both streams (or read the hub aggregate directly when online).

3 · How a session is shared (edge sovereignty)

Each device decides, at session granularity, two orthogonal policies. Both implemented with the same filter_subject lever the spike used for loop-prevention.

Three invariants the implementation must uphold

  1. Catch-up respects share. /api/digests + /api/sessions/{id}/events filter to shared set, or app backstop leaks what transport correctly withheld.
  2. Store retention always keeps your own sessions; mirror others' only where opted in.
  3. Revocation is a known hard edge. Un-sharing drops the source instantly; purging already-propagated copies is the revocability problem — named, not assumed free.
