Ops MCP, drawn

Where the OpenStory ops MCP sits in a node and what it does, split into views that fit on a screen. The rule under all of it: tier 0 hands read; tier 1 hands change only what is derived and leave a proposal on the bus; tier 2 is a proposal a person or the host carries out.

One node, observed lane only. Transcripts become events, events become streams, actors read the streams into the store, and the API reads the store. The presence beat is the node telling the fleet how it feels.

The MCP is a process on stdio between an agent and the node, with exactly two edges. Over REST it reads. Over NATS it subscribes to the observed and authored lanes and publishes only proposals. Nothing it does writes to the observed lane.

Other nodes are reached only through the bus. A node publishes its own events and beats on host-scoped subjects; the hub aggregates every node's streams; each node mirrors the aggregates back. fleet_presence reads the result from the local store, never from another machine.

One tier-1 act, exactly as the code runs it. The MCP reads the verdict, refuses if the node isn't serving, publishes the proposal first and stops if it can't, then calls the node. The node checks the phase again, answers a seen key from its record without acting, or acts and records the command.

The watch motion. subscribe_health answers once with the current verdict, then polls and speaks only when something moves. Silence means nothing changed; an unreachable node is itself a transition.

Every tier-1 call carries evidence (finding ids), an idempotency_key (generated when absent), and an author. A seen key is answered from the record with replayed: true and no second act.

Finding ids the verdict can raise: bus_disconnected, leaf_down, replaying, projections_stale, stream_cap:<stream>, consumer_dead:<name>, consumer_restarted:<name>, watcher_quiet:<actor>, publish_failures:<actor>, presence_failures.

  • Never publishes to events.* or local.*; a test reads the crate's own source for every publish.
  • Never restarts anything; tier 2 is a proposal a person or the host carries out.
  • Never reasons about the content of the coding agents' sessions.
  • Refuses tier-1 acts while the node is not serving, on both sides, naming the replay progress.
  • Never acts without a published proposal.
